## 官方2.5M、推荐50M、实战10M：三个数字分别是什么口径

先把官方页面上的原话摆出来，这部分是可以直接查证的。

另外两条常被引用但要留个心眼的：PC端需用浏览器登录TikTok，**LIVE Studio目前仅支持Windows**；以及“官方最低上传带宽2.5Mbps以上”这个说法，它在跨境圈流传很广，但并不是上面那个官方帮助页里的原句，按“被广泛引用的下限”理解更准确。

现在看差距。官方参考码率2Mbps，最低门槛2.5Mbps，中间只剩0.5Mbps缓冲；实战推荐10–20Mbps，是2.5Mbps的**4到8倍**。官方推荐环境50Mbps，又是实战推荐的2.5到5倍。这笔钱买的不是“更快的网”，是**峰值余量和丢包缓冲**。

原因是直播的带宽消耗不是匀速的。码率动态波动，画面一动、场景一切、补光灯一闪，瞬时码率可能冲到平均值的1.5–2倍。带宽没有余量，一冲峰值就丢包，丢包就卡帧，卡帧观众就走。按1080P 30fps推4000–6000Kbps算，实际占用4–6Mbps，推荐10–20Mbps正好是2–3倍余量；如果按官方2Mbps参考码率配2.5Mbps的线，那0.5Mbps缓冲连一次场景切换都扛不住。

还有一个更容易被忽略的点：**直播吃的是上行，你家宽的下行再快也帮不上忙**。100M、500M的家宽，下行能跑满，上行常常只有10Mbps甚至更少，晚高峰被家人一看视频就腰斩。这就是“测速明明很快，一开播就卡”的最常见解释。

## 带宽够了还是卡？先排查这四个更常见的原因

带宽只是四个变量里的一个。按出现频率排，另外三个更值得先查。

**上行被下行掩盖。** 家里500M宽带，下行500Mbps，上行可能只有30Mbps，晚高峰再被抢一波，推流码率直接腰斩。判断方法很土但有效：开播前用测速工具单独看上传速度，用Ping看延迟和丢包，**上行低于目标码率的2倍就别开播**，开了也是给别人看PPT。

**延迟和丢包的硬阈值。** 业内普遍把RTT 200ms以内当作可接受线、150ms以内算理想；丢包2%以下勉强能播，想“丝滑”得压到0.5%以内。要说明的是，这组数字在跨境圈常被说成“TikTok官方标准”，但官方帮助页里并没有对应表述，按经验值看更稳妥。另一个更贴近真实的判断方式是：不看单次Ping值，看15分钟持续推流的码率曲线是否平稳。

**IP不干净，这是TikTok独有的麻烦。** 平台会从三个维度校验出口IP：注册地归属（IP注册地是否与账号注册地、常用登录地一致）、ASN归属（数据中心机房IP还是真实家庭住宅IP）、历史信誉（有没有被标记、有没有违规记录）。机房IP、共享IP、被反复使用的IP，带宽再大也容易被限流甚至0播放。普通VPN和共享VPS在这条上基本必然失败——出口几乎全是机房段，而且被无数人复用。

**设备过载和后台占用。** CPU持续跑在90%以上，编码跟不上，OBS会直接提示“编码过载”。这一项最好解决：降分辨率、换硬件编码器（N卡NVENC、A卡AMF，软编x264对CPU压力大）、关掉后台下载和系统更新。OBS顺手的几个设置：以管理员身份运行、1080P 30fps推4000–6000Kbps（超过8000Kbps收益递减还容易丢包）、码率别硬撑、开启动态码率。至于关键帧和音频采样率，官方参考值是4秒和44.1kHz，网上流传的“2秒”“必须48kHz”与官方页不一致，先按官方来，出问题再逐项测。

顺带说一个判断顺序：如果换设备、调设置、降码率都试过还是卡，且集中在晚高峰，那多半不是带宽不足，而是线路抖动（丢包）。这时候加带宽没用，得换线路。

**新号直接上干净IP还会不会标黄？** 概率大幅降低但不等于零。新号本身权重低，环境只是把“不该扣的分”扣掉，内容和互动还得自己补。

**OBS推流参数按官方的2Mbps还是按实战的4000–6000Kbps？** 官方给的是参考值，实战按1080P 30fps推4000–6000Kbps更稳。关键帧先按官方4秒，音频先按44.1kHz/128kbps，这和网上流传的“2秒”“48kHz”不一致，以官方页为准更安全。
